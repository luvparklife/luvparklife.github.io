1왜 이 문서인가 (30초)

앞의 「동기화 쉬운 설명」 이후, "대량 입력은 시트라야 하지 않나"라는 대표님 질문을 푸는 두 갈래입니다.

결론: 시트를 "양이 많아서" 붙들 이유는 없습니다(그 반대입니다). 대신 대표님의 대량 입력 손맛을 앱이 갖추게 하면 됩니다. 그 방법이 A(앱에 엑셀식 격자)와 B(깡통 입력시트 → 앱 한 방향) 둘입니다.

지금 아픈 이유

스크립트가 잔뜩 든 시트와 앱을 양쪽으로 맞추려니 계속 부딪힙니다. 시트 스크립트가 스스로 값을 지우고·되돌리고·5분마다 자동으로 돌기 때문입니다. → 주인을 하나(=앱)로 정하면 이 싸움이 사라집니다.

대표님의 진짜 필요 — 대량 입력 손맛 3가지

📥
(a) 줄 한꺼번에프로젝트 하나에 장비 수십 줄
👀
(b) 한눈에 훑기전체를 쭉 보며 관리
↕️
(c) 복사·드래그쫙 채우는 일괄 편집
오해 정정 — "양 = 시트"는 반대입니다. 시트는 원래 500줄 설계인데 실제 자료가 4,773줄(약 10배)이라 열 때마다 몇 분씩 멈춥니다. 반대로 앱 뒤의 데이터베이스는 6,169줄을 4.6초에 읽습니다. 대량일수록 앱이 강합니다. 손맛(a·b·c)은 "용량"이 아니라 "입력 화면"의 문제일 뿐입니다.

A앱에 "엑셀식 격자" 넣기 — 목적지

앱을 유일한 주인으로. 대표님 손맛 3가지를 앱 안에서 그대로. 시트는 완전히 은퇴.

한 문장: 앱 안에 엑셀처럼 생긴 표(격자)를 넣어, 붙여넣기·드래그 채우기·필터를 앱에서 하게 만든다.

손맛 3가지가 앱에서 이렇게 됩니다

대표님 필요앱에서지금 상태
(a) 줄 한꺼번에격자에서 여러 줄 빠른 추가 + 「프로젝트 준비」로 카테고리 골라 수십 줄 자동 생성🟡 일부 있음
(b) 한눈에 훑기「소싱시트 원본 전체 53열」 보기 탭 — 검색·정렬·필터✅ 이미 있음
(c) 복사·드래그격자에서 셀 붙여넣기 · 드래그 채우기 · 여러 줄 골라 한 번에 값 넣기❓ 새로 필요
🔧 명진님께 · 만들 것 (제안)

「소싱시트 · 장비 마스터」 탭을 읽기전용 표 → 편집 가능한 격자로

  • 클립보드 붙여넣기 — 엑셀/시트에서 블록 복사 → 앱 격자에 붙여넣으면 여러 줄·여러 칸 한 번에 입력
  • 드래그(필) 채우기 — 한 셀 값을 아래로 쫙, 여러 셀 선택해 일괄 값 넣기
  • 빠른 신규행 · 열 필터/정렬 · 다중선택 후 일괄수정/삭제
  • 기준키 라인ID는 그대로(자동 부여). 자동계산 칸은 편집 잠금 표시

※ 흔히 쓰는 "데이터 그리드" 방식이면 됩니다. 구체 구현·라이브러리는 명진님 판단. 위는 대표님이 필요한 동작 목록입니다.

이러면 동기화 자체가 필요 없어집니다. 앱이 유일한 주인이니, 시트는 앱이 내보내는 "결과 복사본"(한 방향)만 받는 백업이 됩니다. 시트의 자동 스크립트는 그 복사본에서 끕니다 → 부딪힐 두 번째 운전대가 사라짐.

진행 순서

  1. 소싱·장비 탭에 편집 격자 붙이기 (붙여넣기·드래그·일괄수정)
  2. 시트를 "한 방향 내보내기 백업"으로 전환 · 스크립트 끔
  3. 대표님 실사용 테스트 — 프로젝트 하나를 격자로 시트만큼 빠르게 입력되나
  4. OK면 시트 직접 편집 중단 → 앱이 정식 주인
솔직한 부분: A는 가장 깔끔한 최종 상태지만 격자를 제대로 만드는 개발 시간이 듭니다(흔한 기능이라 가능은 함). 그래서 급한 지금은 아래 B부터 권합니다.

B깡통 입력시트 → 앱 한 방향 — 지금 시도 · 인수인계

대표님은 익숙한 시트에서 편하게 대량 입력하고, 앱이 그걸 받아갑니다. 손맛 유지 + 충돌 없음.

한 문장: 스크립트 없는 "깡통" 시트에 대표님이 쫙 입력 → 앱이 한 방향으로만 가져간다.

왜 이건 안 아픈가 (지금과 정반대)

지금 (아픔)

스크립트 든 시트 ↔ 앱

양방향 + 시트가 자동으로 값을 지우고 되돌림 → 계속 충돌

vs
B (얌전함)

깡통 시트 → 앱

한 방향 + 시트에 자동 스크립트 0 → 부딪힐 게 없음

🔧 명진님께 · 실행 단계 (인수인계)
  1. 새 "입력 전용" 스프레드시트 1개 생성 — 절대 v10 스크립트/수식/트리거 넣지 말 것. 순수 값만 담는 깡통.
  2. 헤더를 앱 sourcing 열 이름과 동일하게 (공백 규칙은 기존 매칭대로 — 공백 제거 후 비교).
  3. 앱에 "입력시트 가져오기(Import)" 한 방향 기능 — 붙여넣기 방식 또는 시트 읽기. 기준키 라인ID(없으면 신규 부여).
  4. 규칙 못박기 — 이 시트는 입력 pad일 뿐. 진실은 앱. 시트 → 앱 한 방향만. 앱 → 시트 되돌림 없음(백업이 필요하면 별도 읽기전용 내보내기로 분리).
  5. 충돌 방지 — 같은 라인ID 중복 입력 정리 · 빈칸은 앱의 채워진 값을 덮지 않음.
  6. 사본에서 먼저 시험 후 안내 — 대표님 원본 시트/v10은 건드리지 않음.

대표님 사용법 (아주 단순)

  1. 깡통 입력시트에 평소처럼 쫙 입력 (복사·드래그 다 됨 — 그냥 구글시트니까)
  2. 앱에서 「가져오기」 한 번 → 입력한 게 앱에 반영
B의 한계 (알고 쓰기): 입력 pad는 "새로 추가 · 초기 대량입력"에 최적입니다. 이미 들어간 값을 고치는 건 앱에서 하세요. 같은 줄을 시트와 앱 양쪽에서 동시에 고치지 않는 것이 한 방향 원칙입니다. (이 습관만 지키면 충돌 0)
B의 좋은 점: 지금 바로 시도 가능 · 대표님 손맛 그대로 · 스크립트 충돌 없음 · A(격자)를 만드는 동안의 임시 다리로 완벽.
